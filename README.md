# STAR 学习助手

> 越用越懂你的 AI 课堂助教
>
> 面向《机器学习预测材料性质》等材料学科交叉课程 · 全班共用一个链接 · 已在阿里云服务器跑通

我们想做的，是一位懂这门课、也懂你的 AI 助教。它依据课堂资料回答，而不是凭空发挥；它在互动中记住你，越用越懂你；它让每一次学习有始有终，成长看得见。

---

## 一、一堂"材料+AI"课的真实困境

《机器学习预测材料性质》是一门典型的交叉课：横跨材料科学与机器学习，选课的同学有的来自材料、有的来自化学或物理，编程和机器学习的基础差别很大。我们在教学一线，反复看到四个绕不开的难题：

- **进度难统一**：同一节课，有人还在补 Python，有人已经能跑模型，课堂只能照顾中间。
- **课后没人问**：年轻老师精力有限，很难一对一答疑；同学卡住了，多半只能去问通用 AI。
- **通用 AI 不懂这门课，还可能"编"**：它没看过老师的课件和讲稿，给出的答案似是而非，在专业课里反而帮倒忙。
- **老师"看不见"学情**：只能等考试才知道大家哪里不会，来不及调整。

说到底，课堂之外，缺一位既懂这门课、又懂这个学生的辅导者。STAR 想补上的，正是这位辅导者。

---

## 二、四个关键词，一位助教

我们把对这位辅导者的期待，凝练成四个词。它们不只是理念，而是每一项都已经做出来、能用：

- **立足课堂材料**：回答只来自老师上传的课件和讲稿，不让模型自由发挥。
- **不凭空而谈**：AI 讲的每一句，都能点开、追溯到课件第几页。
- **越用越懂你**：为每个同学维护一份会成长的画像，互动越多，越懂你。
- **有终有始**：从评估到结课，是一次完整的闭环，学了什么、进步在哪，清清楚楚。

### 立足课堂材料：用"私有知识"治住 AI 的胡说

老师把课件、讲稿、资料传上来之后，系统会用 RAG（检索增强生成）把它们做成本地知识库。同学提问时，AI 会先去课件里检索原文，再组织回答——不是"模型好像听说过这门课"，而是"每次都先翻一遍课件怎么说"。这是我们解决专业课上 AI 幻觉的办法。

### 不凭空而谈：让 AI "有据可查"（我们最想让你看到的一点）

当讲解用到课件 PDF 时，回答末尾会出现一个可点击的小标记 ①②；点一下，右侧就滑出课件，自动翻到被引用的那一页，正文会自动让出位置、不被挡住。同学随时能核对：AI 说的，到底对不对、出处在哪。讲稿和资料也会被参考，但只有课件出处会被编号——保证每个引用都能追到原页。

### 越用越懂你：会成长的三维画像 + 知识图谱

我们借鉴了 Claude Code 的记忆思路，给每位同学建三份画像，并且会随每次学习自动更新：

- **`USER.md`**：你的认知水平、学习习惯、思维方式（比如"更喜欢先看直观例子，再上公式"）。
- **`knowledge.md`**：一本"知识账本"，记录每个知识点你掌握到什么程度（0–4 五级），它同时也是知识图谱的数据来源。
- **`study.md`**：适合你的学习节奏和策略。

你不需要手动去"设偏好"——AI 会在互动中观察你、总结你、适应你。而且掌握度只会升、不会降。首页的知识图谱会实时反映这些变化：节点颜色从灰、绿、蓝绿、蓝到紫，代表从"不了解"到"熟知原理"，进步一眼可见。

### 有终有始：七步学习闭环

每一次学习，都走这样一条路：

> **评估 → 规划 → 情景带入 → 知识讲解 → 练习反馈 → 视频推荐 → 画像更新**

1. 先用一个开放问题把你带入情境，让你主动想，而不是干听；
2. 再把知识拆成小块讲清楚，需要时带上课件出处；
3. 用小练习即时检验、揪出盲区；
4. 到合适的时候，据当前知识点，从老师传的视频里挑 1–3 个最相关的，直接在页面里播放；
5. 走完清单，由你决定什么时候点"完成学习"——点之前不会动你的画像，你可以从容做完练习、继续追问；点之后，AI 才综合这次的表现更新画像、生成学习报告，并回到图谱，提示下一轮该补哪里。

整个过程，你随时能追问、质疑、展开——你不是在机械地按"下一步"。

## 三、给老师：把"看不见的学情"搬上桌面

STAR 不只服务学生。它把全班的学情，汇聚到老师手里：

- **学生管理**：一眼看到全班的姓名、知识点数、平均掌握度、学习次数、最近活跃时间。
- **画像查看**：点开任一同学，能看到他完整的三份画像。
- **班级共性报告**：一键让 AI 聚合全班画像和薄弱点，给出"共性认知 / 共性薄弱点 / 教学建议"，帮老师当场调整教学重点。
- **视频全班均分**：每个视频显示全班评分（比如 ★4.2(12)），方便老师挑出真正有用的资源。

走到这一步，STAR 就从一个"个人学习工具"，变成了课堂的基础设施：学生的每一次学习，都在反过来帮老师把课讲得更好。

## 四、不是 PPT 方案，是真的跑通了

- **单课深耕 + 私有知识**：严格圈定在一门课里，RAG 全链路（提取 → 分块 → 嵌入 → 检索）已经完整做完，PDF / PPTX / DOCX 都支持。
- **画像 + 图谱同源**：画像就是图谱的数据源，两边天然同步，不会对不上。
- **视频推荐 + 评分闭环**：视频按"知识点 + 讲解角度 + 全班评分"来挑；得分低的（3 人以上、均分不到 2.5）会被自动过滤——越用越准。
- **轻量、可复现**：不依赖数据库、不堆框架，JSON + Markdown + FAISS 就能跑；已经在阿里云 Ubuntu（2 核 2G）上部署跑通，全班一个链接就能用。

## 五、育人价值与验证计划

### 我们相信的教育理念，藏在每个设计里

- 情景带入和随时追问，是在培养**主动思考**，而不是被动接收；
- 知识图谱和五级掌握度，让学习**看得见、有结构**；
- 引文可追溯，是在养成"**说话要有依据**"的习惯；
- 班级报告反哺教学，让**教与学互相成就**。

### 验证计划（用真实试用数据，替换纸面的预期值）

我们会在深圳理工大学招募 10–20 名师生，开展 2 周试用，用前后测看知识掌握的变化，用 SUS / NPS 量化体验，并对老师做访谈，评估班级报告和课堂概要到底有没有用。

我们重点盯的过程指标（试用后校准）：画像完整率、单次学习的互动轮数、视频点击率、薄弱点再学率。

## 六、我们清楚自己的边界

不想把话说得太满，当前的不足和接下来的打算，都写在这里：

- **多人同时学习**：现在 LLM 是同步调用的，几个同学同时流式学习会互相等。小班没问题，后续会换成异步，撑住更大的班级。
- **密钥与上传**：自配的 API key 是明文存的、视频是整文件读进内存的，之后会做加密存储和分块上传。
- **能力扩展**：还会加论文辅助阅读、异步并发、HTTPS 正式上线等。

**进度**：核心闭环（多用户、RAG、画像、图谱、视频评分、PDF 引文、班级报告、课堂概要、部署）已经完成 → 目前在小范围试用 → 接下来据反馈迭代，并申请软著。
